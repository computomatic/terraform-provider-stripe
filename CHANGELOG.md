## Unreleased

- New resources, each beside its data source: `stripe_file`, which uploads the local file that `source` names to the Files API host with its `purpose` and records the SHA-256 of its content in `source_sha256`, and Treasury money movement on a connected account, `stripe_treasury_inbound_transfer`, `stripe_treasury_outbound_transfer`, `stripe_treasury_outbound_payment`, `stripe_treasury_credit_reversal` and `stripe_treasury_debit_reversal`. Stripe deletes none of them, so destroying or replacing one fails at plan time, and so does changing a file's `purpose` or the content of its `source`; a new path to the same content changes nothing in Stripe. A file that does not exist yet when the plan runs, such as one another resource writes in the same apply, is read and uploaded at apply time. A file gone from the path it was uploaded from, as on a machine that never had it, changes nothing: the plan keeps the recorded hash and warns that it did not compare the content. The Treasury resources move money, so `allow_live_money_movement` guards them. Setting `status` to `canceled` cancels an inbound transfer, outbound transfer or outbound payment that is still processing. Stripe posts an outbound payment, and an outbound transfer, by itself within about a second; the state reads `posted`, and a plan that then sets `canceled` fails. An inbound transfer needs a bank account attached to the connected account itself, which the provider does not attach; see the Managing Test Data guide.
- An action that sets `status` and that Stripe refuses because it moved the object on by itself while the request was sent, such as the cancel of a top-up that has just succeeded, fails the apply with Stripe's refusal and the status Stripe left, which the state then holds, so the next plan sees it.

- `stripe_shipping_rate.type` is required: Stripe refuses a shipping rate without it and has no default. Set `type = "fixed_amount"`.
- Values Stripe fills in when the configuration leaves them out no longer fail the apply with an inconsistent result, and keep their value on later plans: `payment_settings` and `trial_settings` of `stripe_subscription`, `invoice_creation` of `stripe_payment_link`, `address.line2` of `stripe_terminal_location` and `name` of `stripe_terminal_configuration` (Stripe answers both with an empty string).
- `stripe_issuing_card` reads `number` and `cvc` through a retrieve after each create and update, because Stripe refuses to expand them on any other request; until now every create failed.
- Fields Stripe changes along with another change no longer fail the apply with an inconsistent result: `effective_at` of `stripe_credit_note`, which Stripe sets to the note's creation time, `rendering` of `stripe_invoice` when it is finalized, which turns a page size of `auto` into one Stripe picks, and `cancellation_details` of `stripe_subscription` when `cancel_at_period_end` changes.
- A `stripe_account_v2` closed with `closed = true` keeps in state every field Stripe returns as null once the account is closed, such as `identity`, `configuration` and `display_name`, so later plans are empty and never try to replace it.
- A plan that changes a closed `stripe_account_v2` fails at plan time, because Stripe refuses any change to a closed account; until now it failed at apply with a permission error. An import of a closed account into a configuration that sets the fields Stripe returns as null fails the same way, instead of planning a replacement; ignore every change with `lifecycle { ignore_changes = all }` to import it.
- `stripe_refund.customer` takes the payment intent's customer, which Stripe fills in, when the configuration leaves it unset; until now such a refund failed the apply with an inconsistent result.
- `stripe_account_person_v2.id_numbers` holds only the configured ID numbers, matched by `type`. A minute or two after it creates a person with a `us_ssn_last_4`, Stripe also lists a `us_ssn`, which made later plans fail with "Changing `id_numbers` is not supported yet" on an unchanged configuration.
- `stripe_radar_value_list.alias` and the data source's `alias` lookup refuse upper-case letters at plan time: Stripe stores an alias in lower case and finds a list only by that form.
- Changing `tax_behavior` of a `stripe_price` or `stripe_shipping_rate` once it is `inclusive` or `exclusive` replaces the object, because Stripe refuses the change; from `unspecified` it still changes in place.
- Dropping a key from a `stripe_billing_credit_grant`'s `metadata` fails at plan time, because Stripe keeps a key sent with an empty value. Set the key to `""` to clear its value.
- A destroy whose object is already gone succeeds, such as that of an invoice item Stripe deleted along with its draft invoice: when Stripe refuses the delete and a retrieve then finds nothing, the object is out of the state.
- A new provider argument, `stripe_context` (or the `STRIPE_CONTEXT` environment variable), is sent unchanged as the `Stripe-Context` header of every request, which organization keys (`sk_org_...`) need. It cannot be combined with `stripe_account`. Organization keys themselves are not tested.
- Resources for objects that move money, for managing test data: `stripe_payment_intent`, `stripe_charge`, `stripe_refund`, `stripe_invoice`, `stripe_credit_note`, `stripe_checkout_session`, `stripe_payout`, `stripe_topup`, `stripe_transfer`, `stripe_transfer_reversal` and `stripe_application_fee_refund`, each beside its data source. A new provider argument, `allow_live_money_movement` (default false), makes them, and `stripe_climate_order`, whose create spends the account's balance, fail at plan time in a live-mode account; the provider asks Stripe for the account's mode with `GET /v1/balance`, so a restricted key needs the Balance read permission to create or change one. Stripe cannot delete these objects, so destroying or replacing one fails at plan time, except a draft invoice, which destroy deletes along with the invoice items on it. `status` confirms, captures or cancels a payment intent, finalizes, pays, voids or marks uncollectible an invoice, voids a credit note, expires a checkout session and cancels a pending top-up, and `captured` captures a charge. A refund takes a `payment_intent` or a `charge`. See the Managing Test Data guide.
- Ending an object is a change of its `status`: set it to `canceled` to cancel a `stripe_quote`, `stripe_setup_intent`, `stripe_climate_order` or `stripe_identity_verification_session`, to `canceled` or `released` to cancel or release a `stripe_subscription_schedule`, and to `inactive` to deactivate a `stripe_billing_feedback_option`.
- Connect: the `stripe_account` resource and data source for connected accounts, the `stripe_account_external_account` resource and data source for their bank accounts, and the `stripe_account_capability` data source. Destroying the default bank account of a currency fails at plan time. A `stripe_account` takes the onboarding arguments a US Custom individual account needs for its `card_issuing`, `transfers` and `treasury` capabilities to activate: `business_type`, `individual`, `company.name`, `external_account`, `tos_acceptance`, the Issuing and Treasury terms under `settings`, and the business profile's `mcc`, `url`, `product_description`, `annual_revenue` and `estimated_worker_count`. They are sent on creation only, and a plan that changes one on an existing account fails instead of replacing it. `individual.id_number` and `individual.ssn_last_4` are sensitive and stay as configured, because Stripe never returns them.
- New resources, each with a data source: `stripe_billing_alert`, `stripe_tax_id` and `stripe_customer_balance_transaction`. A tax ID is created through `/v1/tax_ids` with an `owner` of `self` or a customer. A customer balance transaction cannot be deleted, so destroying or replacing one fails at plan time. Destroying an alert deactivates it, and setting its `status` to `archived` archives it.
- New data source: `stripe_customer_cash_balance_transaction`.
- New resource with a data source: `stripe_test_helpers_test_clock`. Setting a later `frozen_time` advances the clock in place and waits until it is ready; setting an earlier one fails at plan time. Destroying a clock deletes the customers on it and cancels their subscriptions.
- New data sources: `stripe_payout`, `stripe_topup`, `stripe_radar_early_fraud_warning`, `stripe_review` and `stripe_invoice_payment`, and `stripe_invoice_line`, `stripe_credit_note_line`, `stripe_quote_line_item` and `stripe_quote_computed_upfront_line_item`. Stripe has no retrieve for a line, so the line data sources find a line by its `id` among the lines of its parent, which they take as `invoice`, `credit_note` or `quote`.
- Issuing and Treasury, which Stripe runs on a platform's connected accounts: manage them through a provider configuration whose `stripe_account` is the connected account. New resources, each with a data source: `stripe_issuing_cardholder`, `stripe_issuing_card` (virtual cards) and `stripe_treasury_financial_account`. Destroying a cardholder or a card deactivates it (`status = inactive`), because Stripe deletes neither; setting a card's `status` to `canceled` cancels it, a canceled card cannot be activated again, and destroying one fails at plan time. Stripe cannot delete a financial account, so destroying or replacing one fails at plan time, and so does a plan that changes its `features`.
- New data sources: `stripe_treasury_transaction`, `stripe_treasury_transaction_entry`, `stripe_treasury_received_credit`, `stripe_treasury_received_debit`, `stripe_treasury_credit_reversal`, `stripe_treasury_debit_reversal`, `stripe_treasury_inbound_transfer`, `stripe_treasury_outbound_transfer` and `stripe_treasury_outbound_payment`, and `stripe_financial_connections_account` and `stripe_financial_connections_session`, `stripe_financial_connections_transaction`, looked up by `id`, and `stripe_financial_connections_account_owner`, which finds an owner by its `id` among the owners of its `account`'s latest ownership, or of the `ownership` it names. A linked account has owners only after an ownership refresh and transactions only after a subscription to transactions, which these data sources never start.
- New data sources: `stripe_billing_credit_balance_transaction`, `stripe_entitlements_active_entitlement`, `stripe_invoice_rendering_template`, `stripe_tax_transaction`, `stripe_tax_location`, `stripe_reporting_report_run`, `stripe_event_v2` (a `/v2` event), `stripe_identity_verification_report`, `stripe_payment_record` and `stripe_commerce_product_catalog_import_v2`, each looked up by `id`, and `stripe_payment_intent_amount_details_line_item` and `stripe_tax_transaction_line_item`, which find a line item by its `id` among the items of its `payment_intent` or `transaction`.
- New data source: `stripe_billing_meter_event_summary`, the usage a meter recorded for a customer over a window, looked up by `meter`, `customer`, `start_time` and `end_time`, because Stripe lists summaries only by those.
- New data source: `stripe_apps_secret`, a Secret Store secret looked up by `name` and `scope`. Its `payload` is sensitive. A verification report's identity data and a catalog import's upload and error file URLs are sensitive too.
- The rest of Issuing, on a connected account. New resources, each with a data source: `stripe_issuing_personalization_design` and `stripe_issuing_dispute`. A design takes its card logo as the ID of a file uploaded with the purpose `issuing_logo`, and a plan that changes its `physical_bundle`, `card_logo` or `carrier_text` fails. Setting a dispute's `status` to `submitted` submits it; once Stripe decides the dispute, `status` reads `won` or `lost`, and `submitted` in the configuration plans no change. An `expired` dispute cannot be submitted, so a configuration that sets `submitted` then fails the plan. Stripe deletes neither, so destroying or replacing one fails at plan time; a design keeps its `lookup_key`.
- New data sources: `stripe_issuing_physical_bundle`, `stripe_issuing_authorization`, `stripe_issuing_transaction` and `stripe_issuing_token`.
- More of Connect. New resources, each with a data source: `stripe_account_person`, a person of a connected account's business, whose `id_number` and `ssn_last_4` are sensitive and stay as configured because Stripe never returns them; `stripe_account_v2`, an account created through Stripe's `/v2` Accounts API with its customer, merchant and recipient configurations; and `stripe_account_person_v2`, a person of such an account. Stripe cannot delete a `/v2` account, so destroying or replacing one fails at plan time; set `closed` to `true` to close it. New data source: `stripe_apps_install`.
- Connect money movement and a customer's legacy payment sources. New data sources: `stripe_transfer` and `stripe_application_fee`, looked up by `id`; `stripe_transfer_reversal`, `stripe_application_fee_refund`, `stripe_customer_card` and `stripe_customer_bank_account`, looked up by their parent (`transfer`, `fee` or `customer`) and `id`.
- New data sources: `stripe_checkout_session_line_item` and `stripe_payment_link_line_item`, which find a line item by its `id` among the items of its `checkout_session` or `payment_link`, because Stripe has no retrieve for one.
- The docs lead with restricted API keys, which Stripe recommends over secret keys: one key per workspace or pipeline with only the permissions its configuration needs, an access policy on every live-mode key, rotation and expiry, and the key supplied through `STRIPE_API_KEY` from a secrets store. A new Using Restricted Keys guide lists the permission each resource and data source needs, as Stripe's API permissions reference names it, and marks unverified the rows whose endpoints that reference does not list.

## 0.1.0 (2026-10-22)

The first release of the Stripe provider for Terraform and OpenTofu, published as `computomatic/stripe`.

- Every request is sent with Stripe API version `2026-09-30.endive`.
- Authenticate with a Stripe secret or restricted key, set in the `STRIPE_API_KEY` environment variable or the `api_key` argument. Use `stripe_account` to manage a connected account with its platform's key.
- 37 resources:
  - Products and pricing: `stripe_product`, `stripe_price`, `stripe_plan`, `stripe_product_feature`, `stripe_entitlements_feature`, `stripe_coupon`, `stripe_promotion_code`, `stripe_shipping_rate`, `stripe_product_catalog_trial_offer`.
  - Customers and payment methods: `stripe_customer`, `stripe_customer_payment_method`, `stripe_setup_intent`, `stripe_payment_method_configuration`, `stripe_payment_method_domain`, `stripe_apple_pay_domain`.
  - Billing and subscriptions: `stripe_subscription`, `stripe_subscription_item`, `stripe_subscription_schedule`, `stripe_invoiceitem`, `stripe_quote`, `stripe_billing_meter`, `stripe_billing_credit_grant`, `stripe_billing_feedback_option`, `stripe_billing_portal_configuration`.
  - Payments and checkout: `stripe_payment_link`.
  - Tax: `stripe_tax_rate`, `stripe_tax_registration`.
  - Radar: `stripe_radar_value_list`, `stripe_radar_value_list_item`.
  - Terminal: `stripe_terminal_configuration`, `stripe_terminal_location`, `stripe_terminal_reader`.
  - Climate and Identity: `stripe_climate_order`, `stripe_identity_verification_session`.
  - Webhooks and files: `stripe_webhook_endpoint`, `stripe_event_destination_v2`, `stripe_file_link`.
- Destroy follows each object's lifecycle in Stripe. `terraform destroy` deletes an object where Stripe has a `DELETE` and archives it where Stripe has a reversible deactivation. Otherwise it fails at plan time, as does a change that would replace the object, and the error shows how to remove the object from the state with a `removed` block (Terraform 1.7 or later, OpenTofu 1.10 or later) or `terraform state rm`. Destroy never cancels, voids, expires or detaches anything. Each resource page says what its destroy does.
- 56 data sources, which read most of the objects above and others that Stripe does not let you create through the provider, such as `stripe_charge`, `stripe_payment_intent`, `stripe_refund`, `stripe_dispute`, `stripe_invoice`, `stripe_credit_note`, `stripe_checkout_session`, `stripe_balance`, `stripe_balance_transaction`, `stripe_event`, `stripe_file`, `stripe_mandate`, `stripe_country_spec` and `stripe_tax_code`. The `docs/data-sources` pages list them all.
